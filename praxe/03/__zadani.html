Kontext (proč to děláme)

Jakmile bude ve škole víc serverů (SRV1-DC, SRV2-FS) a desítky klientů, nikdo si nebude pamatovat IP adresy. Potřebujeme, aby se dalo psát jména jako srv2-fs.<prijmeni>.cyberschool.internal místo 192.168.N.20 — a aby to fungovalo i opačně (podle IP zjistit jméno stroje), což se hodí při řešení problémů, zabezpečení a v logách.

Pravidlo pro pracoviště: Ve vzorovém postupu je číslo pracoviště 200 a příjmení novak. Vy všude dosaďte číslo svého pracoviště (192.168.N.x, kde N je číslo pracoviště) a své příjmení bez diakritiky (prijmeni.cyberschool.internal).

Předpoklad: hotový Modul 00, Modul 01 a Modul 02

Tento modul předpokládá, že server SRV1-DC je řadičem domény lesa <prijmeni>.cyberschool.internal z Modulu 01. Má statickou IP adresu 192.168.N.10/24 na interním rozhraní Ethernet1, výchozí bránu 192.168.N.1, integrovanou roli DNS Server a aktivní DHCP Server z Modulu 02. Klientská stanice PC1-WIN má nainstalovaný systém Windows 11 a získává parametry sítě přes DHCP nebo staticky.

Cílový stav: Plně funkční DNS infrastruktura

Na konci tohoto modulu bude role DNS Server na serveru SRV1-DC plně nakonfigurována pro dopředné i reverzní dotazy:

Parametr Hodnota na SRV1-DC (Server) Hodnota na PC1-WIN (Klient) Poznámka
Role serveru DNS Server, AD DS, DHCP Klient (Windows 11) Správa přes konzoli dnsmgmt.msc
Interní rozhraní (NIC 2) Ethernet1 Ethernet1 Na rozhraní NIC 1 (Ethernet0 / NAT) nikdy nesahejte
Primární dopředná zóna <prijmeni>.cyberschool.internal Dotazuje se na zónu Integrovaná v Active Directory
Reverzní zóna N.168.192.in-addr.arpa Dotazuje se na reverz Zóna pro podsíť 192.168.N.0/24
Zabezpečení aktualizací Secure only (zabezpečené) Zápis přes Kerberos Chrání zónu před neoprávněným přepsáním
Záznam SRV1-DC A (.10) + PTR (10 → srv1-dc) Překládá na .10 Záznam řadiče domény a DNS serveru
Záznam SRV2-FS A (.20) + PTR (20 → srv2-fs) Překládá na .20 Staticky zadaný záznam budoucího serveru
Alias CNAME ftp CNAME ftp → srv2-fs... Překládá ftp na .20 Alias služby pro plánovaný FTP server
Klient PC1-WIN v DNS Dynamický A + PTR záznam Využívá DNS 192.168.N.10 Registrace přes DHCP nebo ipconfig /registerdns

Klíčové vlastnosti cílového stavu:

  1. Dopředná zóna (Forward Lookup Zone): Zóna <prijmeni>.cyberschool.internal je integrována v Active Directory, replikuje se na řadiče v doméně a má zapnuté zabezpečené dynamické aktualizace (Secure only). Obsahuje záznamy A pro SRV1-DC (.10), statický záznam SRV2-FS (.20) a stanici PC1-WIN.
  2. Reverzní zóna (Reverse Lookup Zone): Vytvořená AD-integrovaná reverzní zóna pro síť 192.168.N.0/24 s názvem N.168.192.in-addr.arpa. Umožňuje bezchybný překlad IP adresy zpět na doménové jméno (FQDN).
  3. Konzistentní PTR ukazatele: Pro SRV1-DC je manuálně doplněn chybějící PTR záznam pro adresu .10 (protože řadič vznikl před založením reverzní zóny). Pro SRV2-FS je vytvořen PTR záznam pro .20.
  4. Služební alias CNAME: V dopředné zóně existuje alias ftp.<prijmeni>.cyberschool.internal odkazující na srv2-fs.<prijmeni>.cyberschool.internal. Uživatelé se ke službě připojují obecným jménem služby, nikoliv jménem serveru.
  5. Ověřený obousměrný překlad: Příkazy nslookup srv2-fs, nslookup 192.168.N.20 i nslookup ftp z klientské stanice vracejí korektní odpovědi bez chyb Non-existent domain.

Postup konfigurace v PowerShellu

Krok 1: Kontrola stavu role DNS a dopředné zóny na SRV1-DC:

PowerShell (Spustit jako Administrator na SRV1-DC) 
Get-Service -Name DNS | Select-Object Name, Status, StartType
Get-DnsServerZone -Name "$((Get-ADDomain).DNSRoot)" | Select-Object ZoneName, ZoneType, ReplicationScope, DynamicUpdate
Get-DnsServerResourceRecord -ZoneName "$((Get-ADDomain).DNSRoot)" -RRType A -Name "srv1-dc"

Krok 2: Vytvoření AD-integrované reverzní zóny pro síť 192.168.N.0/24 na SRV1-DC:

PowerShell (Spustit jako Administrator na SRV1-DC) 
$wsX = (Get-NetIPAddress -InterfaceAlias Ethernet1 -AddressFamily IPv4).IPAddress.Split('.')[2]
Add-DnsServerPrimaryZone -NetworkId "192.168.$wsX.0/24" -ReplicationScope "Domain" -DynamicUpdate "Secure"

Krok 3: Statický záznam A a PTR pro budoucí server SRV2-FS na SRV1-DC:

PowerShell (Spustit jako Administrator na SRV1-DC) 
$domain = (Get-ADDomain).DNSRoot
$wsX = (Get-NetIPAddress -InterfaceAlias Ethernet1 -AddressFamily IPv4).IPAddress.Split('.')[2]
Add-DnsServerResourceRecordA -Name "srv2-fs" -ZoneName $domain -IPv4Address "192.168.$wsX.20" -CreatePtr

Krok 4: Vytvoření aliasu CNAME ftp pro plánovanou službu na SRV1-DC:

PowerShell (Spustit jako Administrator na SRV1-DC) 
$domain = (Get-ADDomain).DNSRoot
Add-DnsServerResourceRecordCName -Name "ftp" -HostNameAlias "srv2-fs.$domain" -ZoneName $domain

Krok 5: Doplnění chybějícího PTR záznamu pro řadič SRV1-DC na SRV1-DC:

PowerShell (Spustit jako Administrator na SRV1-DC) 
$domain = (Get-ADDomain).DNSRoot
$wsX = (Get-NetIPAddress -InterfaceAlias Ethernet1 -AddressFamily IPv4).IPAddress.Split('.')[2]
Add-DnsServerResourceRecordPtr -Name "10" -ZoneName "$wsX.168.192.in-addr.arpa" -PtrDomainName "srv1-dc.$domain"

Krok 6: Kontrola síťové konfigurace klienta a dynamická registrace na PC1-WIN:

PowerShell (Spustit jako Administrator na PC1-WIN) 
Get-DnsClientServerAddress -InterfaceAlias Ethernet1 -AddressFamily IPv4
ipconfig /registerdns
ipconfig /flushdns

Krok 7: Ověření překladu jmen, adres a aliasů na PC1-WIN:

PowerShell / Příkazový řádek (PC1-WIN) 
# Dopředný dotaz na A záznam:
nslookup srv2-fs

# Reverzní dotaz na PTR záznam (dosaďte číslo vašeho pracoviště):
nslookup 192.168.N.20
nslookup 192.168.N.10

# Dotaz na alias CNAME:
nslookup ftp

# Ověření odezvy přes doménové jméno:
ping srv2-fs

Ověření nástroji

Na serveru SRV1-DC je dostupná grafická konzole DNS Manager (dnsmgmt.msc):

  • Forward Lookup Zones → <prijmeni>.cyberschool.internal: Obsahuje záznamy A pro srv1-dc (192.168.N.10), srv2-fs (192.168.N.20), PC1-WIN a alias (CNAME) ftp ukazující na srv2-fs.<prijmeni>.cyberschool.internal.
  • Reverse Lookup Zones: Obsahuje zónu N.168.192.in-addr.arpa se záznamy PTR pro 10 (srv1-dc) a 20 (srv2-fs).
  • Všechny zóny jsou typu Active Directory-Integrated Primary s dynamickými aktualizacemi Secure only.
